# Policy reference

`guards/policy.json` states only what differs from the defaults (`DEFAULTS` in `scripts/guardlib/policy.py`). Unknown fields are rejected so that a typo cannot silently disable something. Loosening any field relative to the base branch is `locked` (see `contract.md`). Keep the file short: a project that accepts the defaults needs little more than its guard list.

```json
{
  "version": 2,
  "paths": {"generated": ["src/api/client/**"], "logic": ["src/components/**/use*.ts"]},
  "roles": {"public-api": ["src/index.ts"], "perf-critical": ["src/engine/**"]},
  "thresholds": {"fn-complexity": {"limit": {"logic.python": 15}}},
  "guards": [
    {"name": "secrets", "builtin": "secrets", "tier": "fast"},
    {"name": "complexity", "run": "lizard --csv {root}", "parse": "lizard", "tier": "fast",
     "requires": ["lizard"], "version": "lizard --version"}
  ]
}
```

## Top-level fields

| Field | Default | Meaning |
|---|---|---|
| `base` | `null` = `origin/HEAD`, then `origin/main`, `origin/master`, `main`, `master` | Base ref. The change is merge-base(base, HEAD) against the working tree. |
| `runner` | `tools/guard` | Where `guard.py` lives. Protected, and excluded from every scan. |
| `exclude` | `[]` | Paths no guard looks at. Prefer a code kind: excluded code also escapes the secrets and suppression guards. |
| `paths` | see below | Code kind -> globs. Project globs are matched before the defaults. |
| `roles` | see below | Change role -> globs, merged with the defaults. |
| `security_pattern` | auth, session, password, token, crypto, permission, ... path segments | Regex marking security-sensitive paths. |
| `risk` | strict roles, 600 lines, 40 files, fast roles `docs` | How the verification tier is computed. |
| `thresholds` | see below | Metric limits per code kind and language. |
| `scope_tolerance` | `0.05` | How much smaller than the baseline's a scan may be. |
| `protected` | CI files, CODEOWNERS | Extra protected globs. They add to the defaults, the runner directory and the scripts guard commands run; the defaults cannot be removed. |
| `languages` | `{}` | Extra source extensions, `{".gleam": "gleam"}`. Files whose extension is in neither this map nor the built-in table (60+ languages) are not code: no size, suppression, test-change or kind handling. |
| `guards` | `[]` | The guard list. |

Globs: `*` matches within one path segment, `**/` matches zero or more directories, `{a,b}` alternatives, `?` one character.

## Code kinds

Matched in this order; the first match wins; code matching nothing is `logic`.

| Kind | Default globs (abridged) | Why it differs |
|---|---|---|
| `generated` | `*.generated.*`, `*.pb.go`, `*_pb2.py`, `*.g.dart`, `*.min.js`, `generated/`; or a generator header (`Code generated … DO NOT EDIT`, `@generated`, `<auto-generated`) | Excluded from source guards; checked for drift instead |
| `vendor` | `vendor/`, `third_party/`, `node_modules/`, `Pods/` | Not this project's code |
| `migration` | `migrations/`, `migrate/`, `alembic/versions/`, `prisma/migrations/` | Immutable once merged; size and complexity not checked |
| `test` | `tests/`, `__tests__/`, `spec/`, `e2e/`, `*.test.*`, `*_test.go`, `test_*.py`, `*Test.java`, ... | Table-driven tests are long by design; test-skip and focus markers only count here |
| `ui` | `*.jsx`, `*.tsx`, `*.vue`, `*.svelte`, `*.astro` | Declarative markup inflates length and branch counts |
| `model` | `*.d.ts`, `models/`, `schemas/`, `types/`, `entities/`, `dto/` | Data declarations are long but simple |
| `script` | `scripts/`, `tools/`, `bin/`, shell scripts | Glue code |
| `logic` | everything else | The strictest defaults |

Reclassify with project globs when a default is wrong for the repository. For example, add `"logic": ["src/components/**/use*.ts"]` when hooks sit next to components, or `"generated": ["src/api/client/**"]` for a generated client without a header. Moving more files into a laxer kind is a locked change; moving files into `logic` is free.

## Thresholds

| Metric | Reported by | Default mode | Default limits | Notes |
|---|---|---|---|---|
| `fn-complexity` | lizard, the JS detector, any detector | ratchet, warn at 80% | logic 20 (Go 25), model 20, ui 25, script 25; test/migration unchecked | Go's explicit error checks inflate the count |
| `fn-length` | lizard (NLOC) | budget (+10% and +10 lines) | logic 100 (Go 120), model 150, ui 200, script 150 | Budget: a legacy function may take a bug fix without a refactor, but it cannot creep |
| `file-size` | built-in `size` (non-blank lines) | budget (+10% and +50 lines) | logic 600, ui 600, script 800, test 1500 | Model and migration files unchecked |
| `fan-out` | detectors that report it | advisory | logic 20, ui 25 | Coupling signal; rarely worth a failure |

Limits are looked up as `kind.language`, then `kind`, then `*`; `null` turns a kind off. A guard may carry its own `thresholds` override with the same shape. Defaults never derive from the repository's current distribution, because a threshold fitted to today's code would make today's worst code the norm.

A metric with no limit at all (a guard-level `budget` for `metric` guards) tracks every value: `{"direction": "lower" | "higher", "pct": 10, "abs": 50}`.

There is deliberately no default for "definitions per file" or "imports per file". Both are easy to satisfy by meaningless splitting, which is worse than the problem they measure.

## Roles and tiers

Roles describe what a change touches: `docs`, `ci`, `deps`, `build`, `test-config`, `guard` (guard config, lint config, CODEOWNERS, hooks), `infra`, `schema`, `migration`, `security`, plus `public-api` and `perf-critical`, which the project declares. A changed code file also contributes its code kind as a role.

`risk.strict_roles` (default: security, migration, schema, public-api, deps, ci, build, infra, guard, test-config, perf-critical), `risk.strict_changed_lines` (600) and `risk.strict_changed_files` (40) push a change to the `strict` tier; so do deleted test files, removed assertions, and test expectations rewritten next to implementation changes. A change touching only `risk.fast_roles` runs the `fast` tier.

## Guard entries

| Field | Meaning |
|---|---|
| `name` | Lowercase id; names the baseline file and the exception scope. |
| `run` | Shell command, run from the repository root. Placeholders `{root}`, `{out}`, `{tmp}`, `{base}` (also in the commands of built-in guards). Use `{root}` for the scanned tree so baselines can be derived from the base commit. |
| `parse` | Output format: `findings` (default), `sarif`, `eslint`, `junit`, `lizard`, `tsc`, `mypy`, `gcc`, `regex` (with `pattern` named groups `path`, `line`, `rule`, `message`, `level`), `lines`, `number`, `exit`. |
| `builtin` | Instead of `run`: `secrets`, `suppressions`, `size`, `test-changes`, `deps`, `migrations`, `diff-coverage`, `mutation`, `generated` (with `run` + `outputs`), `snapshot` (with `run`), `metric` (with `run` + `budget`). |
| `input` | Report path or glob read after `run` (or produced by an earlier guard via `{tmp}`). The file must be written during the run; a stale or committed report is an integrity failure. |
| `tier` | `fast`, `standard` (default) or `strict`. |
| `when` | Roles; the guard runs only when one of them changed (ignored by `--full`). |
| `requires` | Executables that must be on PATH; missing ones make the run incomplete (exit 3). |
| `required` | `false` makes a missing tool informational. Use it only for tools that cannot exist in some environments. |
| `version` | Command printing the tool version; recorded in the baseline, a mismatch is a rule change. A failing version command is an integrity failure. Pin the tool. |
| `config_files` | Globs of every file besides the code that changes what the tool reports: its configuration at any depth (`**/ruff.toml`), and scripts the command reaches indirectly (`npm run`, `make`). Part of the fingerprint, copied into the base worktree when baselines are derived, and restored from base in trusted runs. |
| `mode`, `modes` | Default mode for findings, and per-rule overrides (`{"cycle": "hard"}`). |
| `ok_exit` | Exit codes that mean "ran fine" (defaults per parser: SARIF and JUnit allow 1, tsc allows 1–2). |
| `advisory_levels` | SARIF/compiler levels reported as advisory (SARIF default `note`, `none`). |
| `timeout`, `repeat`, `strict_sync`, `scope_tolerance`, `min`, `min_score`, `registries`, `outputs`, `budget`, `thresholds`, `note` | See the guard catalog for the guards that use them. `note` is free text. |
